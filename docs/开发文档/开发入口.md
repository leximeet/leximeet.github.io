# 开发入口

从 [GitHub](https://github.com/leximeet) 或 [Gitee](https://gitee.com/leximeet) 的同名仓库开始，两边使用相同源码、规范与本地验证命令。各项目页提供两份入口。

先确定改动属于哪个模块，再进入对应仓库。本站提供阅读路径和整体设计，具体实现与命令以各仓库的 `docs` 为准。

| -------------------------------------- | -------------------------------------------------------------------------------------- |
| 桌面界面、窗口、系统通知、剪贴板、发音 | [Desktop](https://github.com/leximeet/leximeet-desktop) / `docs/开发指南.md`           |
| 事务、积分、阶段、FSRS、冻结判题       | [Core](https://github.com/leximeet/leximeet-desktop-core) / `docs/开发与测试.md`       |
| 网页侧栏、悬浮球、独立业务与适配器     | [Browser](https://github.com/leximeet/leximeet-browser) / `docs/开发指南.md`           |

## 先理解三条边界

1. Desktop 的学习数据只由 Core 写入；Renderer 只提交实际输入，最终分数由 Core 计算。
2. Browser 在连接模式下切换到 ReadingPort/CapturePort 适配器，不复制完整 Desktop Workspace，也不合并独立资料。
3. 公共资源只读，与个人事实分开；固定物料按摘要消费，不动态读取另一个正在开发的仓库。

## 修改与交接

保持小范围、可复现的改动。关键中文注释解释边界、失败和生命周期；不要用逐行翻译淹没代码。更新所属项目 CHANGELOG、任务入口和中文提交说明，再记录真实测试结果。

协议变化先改规范与正反样例，核验冻结清单，再同步消费者。修改学习行为时，需要同时检查阶段、完成量、调度、重放和撤销；仅把两端的表名改成一样，不能保证业务一致。

工作区约定在 `main` 维护，明确暂存本轮文件。推送、PR、tag、Release、商店和外部发布必须取得维护者授权。贡献流程见[贡献指南](贡献指南.md)。
