# 贡献指南

图解遵循[图表规范](../设计文档/图表规范.md)，用标准 Mermaid 描述流程。参考截图只用来观察视觉，不作为工具使用或真实运行的证据。

欢迎改进功能、修复问题，也欢迎补充文档和复核词典内容。先在对应仓库了解职责与现行规则，避免把已经取消的历史设计重新带回来。

## 提交问题

请说明应用/资源/协议版本、OS 与浏览器、独立或连接模式、具体操作入口和期望结果，并提供最小可重复例子。提交前先清理语境、日志和截图中的私人信息。

安全问题不要在公开 Issue 暴露可利用细节、凭据或完整数据库，按对应仓库 SECURITY 的私密渠道报告；渠道尚未启用时先询问维护者，不编造邮箱。

## 修改代码

1. 保持改动围绕一个清楚的问题，优先复用现有边界与事务。
2. 关键逻辑写中文注释；更新所属仓库规范、CHANGELOG 和提交说明。
3. 测试真实失败路径：幂等、状态切换、响应未知、重启、撤销和资料归属。
4. UI 改动提供改前/改后及明暗、窄窗对照；不要只交一张理想截图。
5. 清理本轮可重建产物，保留必要失败证据；不要删私人库、原始来源或其他开发者资源。

协议变更应先修改合同，再同步消费者；已经冻结字节的物料不能交给通用格式化器处理。学习规则要同时核对独立 Browser 和 Core 的语义与固定向量，不要求两者相同 DDL。

## 修改本站

正文只写根 `docs/`，不要在 `website/docs` 另写一份。新增章节同步导航，图片放 `docs/public` 并标明来源。运行：

```bash
npm ci
npm run verify
npm run serve
```

贡献不意味着可以替维护者外部发布。GitHub 推送、PR、tag、Release、Pages 和商店提交按项目授权流程进行。[文档站维护](维护文档站.md)

自有代码和文档使用 AGPL-3.0-only，提交内容须有权以项目许可分发；第三方材料保留原许可与署名。[隐私与许可](../设计文档/隐私与许可.md)
