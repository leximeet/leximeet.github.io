## 开始使用

Desktop：下载匹配 Apple Silicon 的 DMG，打开后把应用拖入 Applications。应用自带 Java 运行环境和 Core Text 词典。当前安装包使用 ad-hoc 签名，没有 Apple Developer ID 签名或公证；系统可能要求在“隐私与安全性”中确认打开可信下载，不要全局关闭 Gatekeeper。Windows/Linux 和 macOS Intel 没有在本版声明为已验收平台。

Browser：解压匹配 Chrome 或 Edge 的 ZIP，在 `chrome://extensions` 或 `edge://extensions` 开启开发者模式，加载包含根 `manifest.json` 的目录。要求 Chromium 142+。连接桌面前，按[插件连接](../使用文档/插件连接.md)安装本机 Host 并确认邀请。GitHub ZIP 发行与浏览器商店审核分别进行。

首次使用步骤与截图见[桌面端](../使用文档/桌面端.md)和[浏览器插件](../使用文档/浏览器插件.md)。

## 核对附件

将同一 Release 的附件和 `SHA256SUMS` 下载到同一目录，执行：

```sh
shasum -a 256 -c SHA256SUMS
```

发行清单记录准确源码提交和实际文件摘要。Desktop 使用子模块；GitHub 自动生成的源码 ZIP 不展开 Core，必须同时保留 Release 的 `desktop-source.tar.gz` 和 `core-source.tar.gz` 才是完整对应源码。不要将不同运行的同名包、旧源码或历史测试报告拼为一份发行物。

## 发布流程

| 项目    | 标签触发后的门禁                                                | 发布阶段                               |
| ------- | --------------------------------------------------------------- | -------------------------------------- |
| Desktop | 完整桌面检查、实际包物料、DMG 隔离安装与启动                    | 复用原样安装器，附两个完整源码包       |
| Browser | 格式/合同/类型/单元、Chrome/Edge 生产等价、完整独立 Chromium UI | 复用通过测试的两个 ZIP，附完整源码     |
| Core    | Linux/macOS/Windows 全部 Maven、文档与真实 `java -jar` 检查     | 复用 Linux 已验收 Jar/SBOM，附完整源码 |
| LMCP    | Node.js 22/24 格式、合同、参考验证与归档                        | 复核原样归档、标签提交和规范摘要       |

检查和构建任务只读，只有最终发布任务允许写 Release；先将全部附件上传到草稿，再统一公开。main 或 PR 推送不创建正式 Release，工作流也不代替维护者创建标签。已公开标签不移动、同版本附件不覆盖；后续生产修复使用新版本。

真实 Browser/Desktop 连接另有独立工作流，需要记录精确的三仓来源。Core 三平台通过不等于 Desktop 三平台安装通过；Chrome/Edge 的字节等价不等于正式 Edge 或商店安装验收。系统权限、声音和人工体验仍按各项目验收范围记录。

文档站从根 `docs/` 构建，部署复用同一次检查通过的静态产物；GitHub Pages 与四个软件 Release 分别核验。主站入口：[leximeet.github.io](https://leximeet.github.io/)。

[发布与版本管理](发布与版本管理.md)介绍双平台同步、标签维护和正式资料保护。各项目的 `docs/版本/1.0.0.md` 是对应组件的详细发行说明。
