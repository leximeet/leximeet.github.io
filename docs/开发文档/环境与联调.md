# 环境与联调

使用隔离空间，不占用日常浏览器 profile、系统剪贴板或个人数据库。可见体验与后台自动门禁是两个入口。

## 环境

| 仓库                  | 构建环境                                               |
| --------------------- | ------------------------------------------------------ |
| Desktop               | Node.js 24+、JDK 21、Maven 3.9；一键脚本可准备缺失工具 |
| Core                  | JDK 21、Maven 3.9；项目隔离 Maven 缓存                 |
| Browser / 协议 / 本站 | Node.js 22.12+，使用锁定 npm 依赖                      |
| Dictionary            | Python 3.11+，固定依赖与来源                           |

Desktop 运行包携带裁剪 JRE 和 Native Host，安装后的连接不要求用户装系统 JDK 或 Node；构建者仍需准备编译环境。

## 本地打包与资料隔离

在已提交且子模块一致的 Desktop checkout 中运行 `npm run release:local`，完成本机安装器构建、物料核对和隔离安装启动检查。每个候选单独保存 `BUILD-MANIFEST.json` 与安装文件校验和；调试命令 `package:dir` / `package:dist` 允许未提交源码，但不表示安装验收已通过。精确输出、运行环境和失败处理见 [Desktop本地打包与安装](https://github.com/leximeet/leximeet-desktop/blob/main/docs/本地打包与安装.md)。

正式 Desktop 沿用稳定的 `workspaces/v1` 资料空间，开发默认 `.runtime/dev-v1`，测试每轮独立；显式指定资料目录时尊重该设置。未发布旧试用库留在原位置，不自动读取、迁移或删除。应用版本变化不会重新建立空白正式资料库。

## 推荐目录布局

```text
workspace/
├─ leximeet-desktop/          # core-java 是锁定子模块
├─ leximeet-desktop-core/
├─ leximeet-dictionary/       # 可选：复用已校验词包
└─ plugin/
   └─ leximeet-browser/
```

Desktop 完整检出使用 `git clone --recurse-submodules`；缺失子模块时运行 `git submodule update --init core-java`。协议快照随消费者保存，不依赖相邻协议仓实时可变内容。

## 人工体验

```bash
# Desktop 仓库：每次创建新空间
bash scripts/test-desktop.sh
# 恢复同一空间，检查重启
bash scripts/test-desktop.sh --resume <空间ID>
# 只读检查，不下载或编译
bash scripts/test-desktop.sh --check
# 实际桌面包 + 专属 Chromium，用户自己配对
bash scripts/test-desktop.sh --connected
```

双端脚本不会向日常 Chrome 注册扩展。首次启动会显示教学，并提供英文阅读页面；终端中的 stop/restart 用于控制本轮 Desktop，检查临时失联后的恢复。新建空间不预置学习成果，关闭后也不应把临时资料当作长期个人库。

Browser 单端体验：

```bash
npm ci
npx playwright install chromium
npm run fetch:dictionary -- --with-core
npm run build
npm run lab:browser
```

## 后台测试

Desktop 的 `bash scripts/test-background.sh` 串行运行隐藏 UI，使用真实 Core/SQLite 和受控 OS 投递，不操作系统键鼠。七天日期通过 test profile 的业务时钟推进，认证期限仍用真实时间，不改操作系统日期。

后台截图和回调证明业务链路，不证明用户看到了系统通知，也不证明扬声器听感。通知权限、真实快捷键、输入法和安装签名另行人工验收。[测试分层](测试与质量.md)

精确脚本行为与清理边界见 [Desktop 本地启动](https://github.com/leximeet/leximeet-desktop/blob/main/docs/本地测试启动.md)和 [Browser 开发指南](https://github.com/leximeet/leximeet-browser/blob/main/docs/开发指南.md)。
